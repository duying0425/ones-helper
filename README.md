# ones-helper

ONES 工时自动计划与填写工具，适用于 `ones.reachauto.com`。

此工具通过分析你负责的未完成任务和剩余预计工时，在当月工作日中自动、合理地分配工时，并支持一键提报与状态流转。**纯 Python 标准库实现，无任何第三方依赖。**

---

## 🌟 核心功能

*   **智能工时分配**：自动查询本月已填工时，精准识别哪些天未满、哪些天有剩余，并根据配置按工作日分配新工时。
*   **多任务规划**：自动拉取跨项目、未完成的活跃任务，默认以任务的“剩余预计工时”为规划基础。
*   **加班工时支持**：当月度常规工时填满后，支持追加加班工时分配（可配置每日加班上限）。
*   **自动化状态流转 (Workflow)**：
    *   **阶段 1**：启动任务（`未开始` ➜ `进行中`）
    *   **阶段 2**：填完提交审核（`进行中` ➜ `完成审核中`，支持过滤条件）
    *   **阶段 2b**：月度容量已满但任务未完成，且计划当月结束时，询问是否提交审核（默认 `N`）
    *   **阶段 3**：任务归档（`完成审核中` ➜ `已完成`）
*   **内置节假日数据**：内置 2025 年官方节假日及 2026 年估算节假日（含补班日），支持通过配置文件灵活增删与覆盖。
*   **安全认证与自动刷新**：
    *   支持解析完整 `cookie_string` 自动提取认证信息。
    *   支持利用 `session_id` 自动刷新即将过期的 `ones-lt` Token。
    *   Token 过期且无法自动刷新时，提供人性化的运行时交互式输入提示。
*   **精美汇总报表**：在提交前后以对齐的表格形式展示本月已填工时、任务状态及项目分布。已完成的任务也会通过 GraphQL 接口逐条查询并详细展现。

## 🚀 快速开始

### 1. 准备配置文件

```bash
# 复制模板文件
cp config.example.json config.json
```

### 2. 获取并填入认证信息

保持登录状态访问 [ones.reachauto.com](https://ones.reachauto.com)。
按 `F12` 打开开发者工具，选择 **Application (应用) ➜ Cookies ➜ ones.reachauto.com**。

有两种配置方式（任选其一）：

*   **方式 A：简化配置（推荐）**
    直接在 `config.json` 中配置 `cookie_string`：
    ```json
    "cookie_string": "将浏览器中 ones.reachauto.com 的完整 Cookie 字符串复制并粘贴到这里"
    ```
    程序启动时会自动从中解析出 `user_id` 和 `auth_token`。

*   **方式 B：常规配置**
    分别提取并填入以下字段：
    
    | `config.json` 字段 | Cookie 键名 | 说明 |
    | :--- | :--- | :--- |
    | `auth_token` | `ones-lt` | JWT 令牌，约 1 小时过期。过期后程序会提示或自动刷新 |
    | `session_id` | `ones-ids-sid` | Session ID，有效期数月，用于自动刷新 `auth_token` |
    | `user_id` | — | 用户的 UUID，通常可留空或从 `ones-uid` / 运行时提示中获取 |
    | `team_uuid` | — | 团队 ID，可在浏览器 URL 中的 `/team/{team_uuid}/` 部分找到 |

### 3. 运行工具

```bash
# 1. 正常运行（规划并提交本月工时）
run.bat

# 2. 预览模式（仅展示工时分配日历与汇总，不修改任何云端数据）
run.bat --dry-run

# 3. 指定月份运行（格式为 YYYY-MM）
run.bat -m 2026-04

# 4. API 调试模式（输出详细的请求与响应数据）
run.bat --debug

# 5. 本地规划/手动模式（不调用任何 ONES 接口，纯本地交互式规划）
run.bat --manual
```

## ⚙️ 命令行参数详解

运行 `python ones_timefiller.py --help` 可查看完整参数说明：

| 参数 | 缩写 | 说明 |
| :--- | :--- | :--- |
| `--month` | `-m` | 指定要填写的月份，格式为 `YYYY-MM`。默认值为当前月份。 |
| `--dry-run` | - | 预览工时分配日历和状态流转计划，不向服务器发送任何写入请求。 |
| `--debug` | - | 启用调试模式，打印 API 请求 URL、Payload 以及 Response。 |
| `--manual` | - | 手动模式。不调用接口获取任务，直接让用户手动输入任务名称和工时进行本地日历规划。 |
| `--team` | - | 覆盖 `config.json` 中的 `team_uuid`。 |

## 🔧 高级配置指南

在 `config.json` 中，你可以自定义许多高级行为：

### 1. 状态流转工作流 (`workflow`)

工作流按任务的工作项类型（如“任务”、“工作任务”等）配置状态流转路径。

```json
"workflow": {
  "任务": [
    {"status": "未开始", "button": "开始任务"},
    {"status": "进行中", "button": "完成任务", "comment": "任务已顺利完成"},
    {"status": "已完成"}
  ]
}
```
*   `status`: 任务的当前状态名。
*   `button`: 触发流转的按钮名称（对应 REST 接口中 `transitions` 的 `name`）。
*   `comment`: 可选，在执行该步骤流转时自动附带的备注信息。
*   **最后一项**只需要 `status` 字段，作为流程的终态。

### 2. 自定义节假日补丁 (`extra_holidays`)

当遇到临时调整放假、或是内置 2026 估算节假日与官方公布不符时，可直接在配置中修正：

```json
"extra_holidays": {
  "off": ["2026-06-01"],         // 新增休息日（即使它是周一到周五）
  "on": ["2026-06-06"],          // 新增工作日（即使它是周六或周日）
  "remove_off": ["2026-02-16"],  // 移除内置的休息日标记（变回普通工作日）
  "remove_on": ["2026-02-14"]    // 移除内置的工作日/补班标记（变回普通休息日）
}
```

### 3. 加班模式 (`overtime_daily_max`)

*   配置项：`overtime_daily_max`（默认值为 `4`）
*   说明：当常规工作日工时（每天 8h）全部填满后，如果任务仍有未填写的剩余预计工时，系统会询问是否追加加班工时。分配时，每日工时上限将调整为 `8 + overtime_daily_max` 小时。

### 4. 北森考勤系统加班策略 (优先使用)

*   **说明**：支持从北森考勤系统 (Italent) 获取当月每天的工作时长，并根据以下规则自动计算加班工时：
    *   `当天加班工时 = 四舍五入(工作时长 - 1小时午休) - 8`
    *   该策略计算出的加班工时将**优先使用**，并自动按天分配在日历中。
*   **如何启用 (三选一)**：
    1.  **离线文件方式 (推荐)**：抓包复制考勤数据接口的 Response JSON，在同级目录下保存为 `attendance.json` (模板见 `attendance.example.json`)。
    2.  **快捷交互粘贴**：直接运行脚本，若未检测到配置，控制台会提示粘贴 Cookie，输入后会自动保存到 `config.json` 并在今后自动使用。
    3.  **配置文件写入**：在 `config.json` 中配置 `"italent_cookie": "你的Cookie"`。
